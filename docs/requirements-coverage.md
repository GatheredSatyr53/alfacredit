## Поставка и документация

- Единый запуск всех четырёх компонентов: `scripts/start-demo.ps1` и `compose.demo.yaml`. Запуск только backend/API отдельно сохранён в README.
- Версии frontend и ML закреплены в скрипте; backend соответствует checkout репозитория. Commit SHA поставки можно получить командой `git rev-parse HEAD`.
- Архитектура и её схема — в README. API — в `api.md`; OpenAPI — в `openapi.json` и Swagger. Коллекции — `postman_collection.json` и `requests.http`.
- Модель данных, состояния и сценарии — в перечисленных документах. Тестовые профили и команды проверки — в `quickstart.md` и README. Языки, библиотеки и контейнеры закреплены в global.json, lock-/requirements-файлах и Dockerfile компонентов.
- Использованные компоненты, модель и симуляции описаны в `THIRD_PARTY_NOTICES.md` и PRODUCT.md.
- Для приватной сдачи владельцы должны проверить право чтения и клонирования у аккаунта жюри `alfa-hack-2026`. Публичный внешний стенд рекомендован; в этой поставке он не заявлен.

## Подтверждённые сценарии и границы

25 октября на рабочей сборке проверены 110 frontend-тестов, 77 проверок сквозных сценариев с внешним ML и 81 проверка резервного режима на отдельном экземпляре API. После перезапуска сохранились 19 существовавших в тот момент заявок и их финансовые данные. Исправление метаданных Git от 26 октября не изменило дерево файлов этой сборки.

26 октября дополнительно проверен единый запуск из backend: frontend и ML скачаны скриптом на закреплённых SHA, контейнеры собраны из исходников, PostgreSQL стартовал на новом томе. Все четыре сервиса стали healthy. Кабинет ответил HTTP 200, API readiness — Healthy, CORS разрешил выбранный адрес кабинета. На изолированных портах 13000/18081/18001 прошли 77 из 77 проверок пяти сквозных сценариев с logreg-synthetic-0.1. Кэш базовых образов и пакетов использовался; установка на полностью пустом Docker-кэше и минимальная память на отдельном ПК с 8 ГБ не измерялись. Нагрузочное тестирование и эксплуатация реального банка не подтверждены.

Внешние проверки, решение менеджера в демо, подтверждение кодом и выдача смоделированы. Нет реальной очереди сотрудника с запросом уточнений, реального SMS и перевода денег. Предварительная оценка вероятности одобрения, OCR и обслуживание долга после выдачи в реализованный основной сценарий не входят. Организаторы не требуют копировать все экраны примера; проверять нужно работающий процесс и его пользу.
